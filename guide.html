왜 우리는 이 과정에서 혼란을 느낄까요?

우리는 웹 LLM을 통해 코드를 만들고, 로컬 PC의 VS Code와 GitHub CLI(`gh`)를 이용해 커밋과 푸시를 해보았습니다. 하지만 명령어와 화면 시퀀스를 그대로 따라 하기만 할 뿐, "지금 내 코드가 어디서 만들어져서 어디로 전달되는지", 그리고 "왜 로그인을 여러 번 하는 것처럼 보이고 인증 창이 뜨는지" 그 실체가 감 잡히기 어려웠습니다.

이 가이드를 통해 파일의 물리적 위치와 보안 인증의 흐름을 머릿속에 확실히 그려보세요!

1

코딩하는 장소와 파일이 전달되는 위치 (아키텍처)

웹페이지가 세상에 공개(GitHub Pages)되려면, 파일이 반드시 GitHub 원격 저장소(Remote Repository)에 존재해야 합니다. 하지만 코드를 작성하는 방법은 크게 두 가지 경로가 있습니다.

경로 A

웹 LLM + 플러그인 방식

  1. 브라우저(웹 LLM): AI와 대화하며 코드를 생성합니다.
  2. 플러그인/API: 브라우저에서 곧바로 GitHub 서버에 연결되어 파일을 전송합니다.
  3. GitHub 저장소: 클라우드 상의 저장소에 파일이 곧바로 기록됩니다.
경로 B

로컬 PC + VS Code / Copilot 방식

  1. 내 컴퓨터(로컬): VS Code에서 파일을 만들고 수정합니다 (내 PC 하드디스크).
  2. Git & GH CLI: 터미널에서 git add, git commit, git push 명령어로 코드를 묶어 전송합니다.
  3. GitHub 저장소: 내 PC의 파일 복사본이 원격 서버(GitHub)로 업로드됩니다.

💡 웹페이지에서 확인하는 소스의 위치는 어디인가요?

학생들이 가장 많이 헷갈리는 점입니다. 내가 브라우저나 내 컴퓨터(로컬 PC)에서 수정한 코드는, 반드시 GitHub 원격 저장소에 푸시(Push)되어야만 GitHub Pages 서버가 그 파일을 읽어서 https://아이디.github.io 주소로 서비스할 수 있습니다. 내 컴퓨터나 웹 LLM 창에만 파일이 남아있다면 다른 사람이나 웹사이트에서는 절대 볼 수 없습니다!

2

GitHub 로그인, 2FA, 그리고 `gh cli` 디바이스 인증의 비밀

계정 로그인, 2단계 인증, 터미널 인증까지 단계가 복잡하게 느껴진 이유는 각각 담당하는 역할이 완전히 다르기 때문입니다. 아래의 3가지 개념을 분리해서 이해하면 수수께끼가 풀립니다.

1

GitHub 웹사이트 로그인 (User Login)

웹브라우저(Chrome 등)에서 github.com에 접속해 아이디와 비밀번호를 입력하는 것입니다. 이는 "내가 이 웹사이트의 주인이다"라는 것을 GitHub 서버에 증명하는 첫 번째 관문입니다.

2

이중인증 / 2단계 인증 (2FA - Two-Factor Authentication)

비밀번호가 해커에게 털리더라도 계정을 보호하기 위한 보안 장치입니다. 로그인 시 스마트폰 인증 앱(Google Authenticator 등)의 6자리 숫자나 패스키를 추가로 요구하여 "진짜 본인 맞는지" 확실하게 더블 체크합니다.

3

`gh cli` 디바이스 인증 (Device Flow) - 가장 혼란스러운 부분!

VS Code 터미널에서 gh auth login을 치면 갑자기 웹 브라우저가 뜨면서 코드를 입력하라고 합니다. 왜 터미널에서 직접 아이디/비밀번호를 안 치고 이런 번거로운 과정을 거칠까요?

  • 보안과 편의성: 검은색 터미널 창에 내 비밀번호와 2FA 코드를 직접 타이핑하는 것은 보안상 위험하고 불편합니다.
  • 일회용 코드(Device Code)의 원리: 터미널이 GitHub 서버에 "나 지금 로그인할게"라고 요청하면, 서버가 8F3A-BC12 같은 일회용 코드를 줍니다.
  • 권한 위임(Authorization): 이미 내 브라우저에서 로그인되어 있는 상태로 그 코드를 입력하면, 브라우저가 GitHub 서버에 말합니다. "이 브라우저 계정의 권한을, 지금 내 로컬 PC의 VS Code 터미널(gh cli) 프로그램에 안전하게 빌려(토큰 발급) 줘!"

즉, `gh cli` 디바이스 인증은 비밀번호를 또 치는 게 아니라, "이미 로그인된 내 브라우저의 힘을 빌려 내 컴퓨터의 개발 프로그램에 출입증(토큰)을 발급해 주는 안전한 절차"입니다.

🎯 수업 핵심 정리 체크리스트

1. 코딩 장소

웹 LLM 혹은 내 로컬 PC(VS Code). 어디서든 코드는 만들 수 있습니다.

2. 푸시와 배포

GitHub 원격 저장소에 푸시되어야만 GitHub Pages 웹사이트에 반영됩니다.

3. 인증의 이해

웹 로그인은 신분증 확인, 2FA는 이중 잠금, `gh cli`는 프로그램에 권한 위임!
