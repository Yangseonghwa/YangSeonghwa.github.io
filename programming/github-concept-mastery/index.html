📦 택배 배송에 비유해 보면?

  • 내 방 책상 (로컬 PC): 내가 직접 물건(HTML 파일)을 만들고 포장하는 곳
  • 우체국 / 물류센터 (GitHub): 내 웹사이트를 전 세계 친구들에게 배달해 주는 서버
  • AI 도우미 (LLM / Copilot): 옆에서 포장을 도와주거나, 멀리서 설계도를 보내주는 조력자

  • 아무나 내 우체국 창고(GitHub 저장소)에 파일을 바꾸면 큰일 나겠죠?
  • 그래서 웹 브라우저로 들어갈 때, 내 PC 터미널이 대신 들어갈 때 각각 알맞은 신분증 검사를 합니다.

🚀 왜 훨씬 빠를까?

  • AI가 내 폴더의 여러 파일(HTML, CSS, JS)을 직접 읽고 수정합니다.
  • 파일을 다운로드하거나 복붙할 필요가 0번입니다.

🔌 GitHub와 바로 연결!

  • 수정이 끝나면 터미널(또는 Copilot 명령)에서 git push로 한 번에 올립니다.
  • 단, 내 PC 터미널이 GitHub 창고에 들어가려면 안전한 출입증(인증)이 필요해요!

인증 원리 지도 웹 로그인 · 2FA · 디바이스 인증

GitHub 인증 3총사: 상황마다 다른 열쇠를 쓰는 이유 🔑

"그냥 아이디랑 비밀번호만 치면 안 되나요?" — 어디서 접속하느냐와 보안 수준에 따라 3가지 인증이 협력합니다.

1️⃣ GitHub 웹 로그인

어디서? 크롬·엣지 웹 브라우저

비유: 집 현관문 열쇠 🏠

아이디와 비밀번호로 내 계정에 들어가는 기본 신분증이에요.

2️⃣ 2단계 인증 (2FA)

어디서? 로그인 직후 스마트폰

비유: 금고 이중 잠금 🔒📱

비밀번호가 뚫려도 내 스마트폰 없이는 절대 못 들어오게 막아요.

3️⃣ gh CLI 디바이스 인증

어디서? VS Code 터미널 (gh)

비유: 대리 출입증 발급 🪪

내 PC 터미널이 브라우저 대신 GitHub에 파일을 올릴 수 있게 허락받아요.

💡 핵심: 웹 로그인 + 2FA로 브라우저에서 "진짜 나"를 증명한 다음, 그 신뢰를 바탕으로 터미널(gh CLI)에 출입증을 발급해 주는 거예요!
[교사 메모] 세 가지가 서로 경쟁하는 다른 기능이 아니라, '1단계 → 2단계 → 3단계'로 이어지는 보안 사다리임을 강조해 주세요.
인증 상세 ① 브라우저만의 출입 팔찌

1단계: GitHub 웹 로그인 — 왜 터미널은 이걸 모를까? 🍪

🌐 브라우저에서 로그인하면 생기는 일

  • github.com에 아이디와 비밀번호를 입력합니다.
  • GitHub 서버가 브라우저에게 쿠키(Cookie) / 세션이라는 '놀이공원 자유이용권 팔찌'를 채워줍니다.
  • 그래서 새로고침해도 로그인이 유지돼요!

🤔 그런데 왜 VS Code 터미널에선 안 될까?

  • 크롬 브라우저와 VS Code 터미널은 서로 다른 프로그램(별개의 방)이에요!
  • 브라우저가 찬 팔찌(쿠키)를 터미널은 볼 수 없기 때문에, 터미널에게는 따로 출입증을 줘야 합니다.
⚠️ 주의: 공용 컴퓨터(컴퓨터실 PC 등)에서 웹 로그인을 할 때는 수업이 끝나면 반드시 로그아웃해야 다음 사람이 내 팔찌를 쓰지 못해요!
[교사 메모] "크롬에서 로그인했는데 왜 git push가 안 되나요?"라는 단골 질문을 완벽히 해결해 주는 슬라이드입니다.
인증 상세 ② 내 계정을 지키는 두 번째 자물쇠

2단계: 2FA (Two-Factor Authentication) — 이중 잠금의 원리 🔐📱

GitHub는 전 세계 개발자들의 코드가 모이는 곳이라 보안이 매우 중요해요. 그래서 2단계 인증(2FA)을 필수로 요구합니다.

🧠 요소 1: 내가 아는 것 (Something You Know)

아이디 & 비밀번호

머릿속에 기억하는 글자 조합이지만, 해킹이나 실수로 유출될 위험이 있어요.

📱 요소 2: 내가 가진 것 (Something You Have)

내 스마트폰 인증 앱 / GitHub Mobile

30초마다 바뀌는 6자리 숫자(OTP)나 스마트폰 승인 버튼으로 '내 손안의 기기'를 확인해요.

✨ 원리 한 줄 요약: 설령 해커가 내 비밀번호를 훔쳐도, 내 주머니 속 스마트폰이 없으면 절대 로그인할 수 없어요!
[교사 메모] 중학생들이 스마트폰을 학교에 안 가져왔거나 인증 앱 설정이 어려울 때는 교사의 안내에 따라 복구 코드(Recovery Codes)를 안전하게 보관하는 습관도 함께 짚어주세요.

구분 핵심 원리 한 줄 정리
웹 LLM vs 로컬 VS Code 웹 LLM은 코드를 직접 복붙·업로드해야 하지만, 로컬 VS Code + Copilot은 내 폴더 파일을 직접 수정하고 바로 푸시한다.
웹 로그인 vs 2FA 웹 로그인은 비밀번호(아는 것), 2FA는 스마트폰 인증(가진 것)으로 이중 잠금을 건다.
gh CLI 디바이스 인증 터미널에 비밀번호를 치지 않고, 8자리 코드 + 브라우저 승인으로 안전한 출입증(토큰)을 PC에 저장한다.
